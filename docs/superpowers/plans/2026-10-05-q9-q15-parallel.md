# Q9 묻고 기다리기 · Q15 음성 — 병렬 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 상시 에이전트가 무인 태스크 중에 소유자에게 채널로 **묻고 `WAITING_USER` 로 기다렸다가** 답을 받아 재개하게 하고(Q9), 채널의 **음성 메시지를 텍스트로 전사**해 대화·에이전트 스레드로 흘려보낸다(Q15).

**Architecture:** 두 트랙은 서로의 코드를 읽지 않는다. 각자 `dev`@`8d149f39` 에서 자기 worktree·브랜치로 돌고, 공유 파일(로드맵·dots 문서·`config/neos.development.yaml`)은 **통합 단계에서 오케스트레이터만** 고친다. Q9 는 Q10b 의 멈춤(한 트랜잭션 전이)·알림 큐·재개 경로와 Q8 의 스레드·세션을 재사용한다. Q15 는 채널 미디어 수집 → 게이트웨이 앞단 전사 → 기존 대화 경로(Q8b 스레드 포함)로 이어 붙인다.

**Tech Stack:** Python 3.12 · FastAPI · asyncpg/SQLAlchemy · Postgres 16 · pytest(실 DB 계약 테스트) · OpenAI 전사 API(`openai>=3.8.0`, 이미 의존성) · Next.js(FE 상태 표시만, 필요할 때)

**Spec:** 정본은 [OPENAI_DOTS_ANALYSIS_260930.md](../../OPENAI_DOTS_ANALYSIS_260930.md) §4.2 의 Q9·Q15 행과 §4.1 원칙. 이 계획의 Phase A 가 트랙별 설계 문서(`docs/Q9_ASK_AND_WAIT_DESIGN_261005.md` · `docs/Q15_VOICE_DESIGN_261005.md`)를 만들고, 그것이 각 트랙의 스펙이 된다. 기반: [Q8 설계](../../Q8_CROSS_CHANNEL_THREAD_DESIGN_261005.md) §10 "Q9 가 Q8 위에 더할 것".

## Review Focus

1. **다른 채널에서 온 답** — Slack 으로 물었는데 소유자가 Telegram DM 으로 답한다 → 재개되어야 한다(같은 스레드의 붙은 세션). Q9 Task 3 에 테스트
2. **질문 대기 중의 엉뚱한 메시지** — 소유자가 질문과 무관한 말을 한다 → 권고대로면 그것이 답이 된다. 확인 문구에 질문 요약을 실어 사용자가 알아차리게 한다. Q9 Task 3 에 "확인 문구에 질문이 들어 있다" 테스트
3. **같은 에이전트의 두 태스크가 동시에 묻는다** — 하나만 대기, 둘째는 `ask_pending` 거절이고 그 태스크는 계속 돈다(멈추지 않는다). Q9 Task 1 에 실 DB 경합 테스트
4. **긴/큰 음성** — 상한을 넘는 오디오는 공급자에 **바이트를 보내지 않고** 거절 문구로 답한다. Q15 Task 1·3 에 "공급자가 불리지 않았다" 테스트
5. **게이트 밖의 음성** — 무시 채널·봇·미매핑 발신자의 음성은 전사하지 않는다(비용·외부 전송). Q15 Task 3 에 "공급자 호출 0회" 테스트
