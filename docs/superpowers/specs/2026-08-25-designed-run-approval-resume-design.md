# 설계된 run 의 승인 재개 — 설계

**작성일:** 2026-08-25
**트랙:** G/H — 워크플로우 그래프 계약 (`docs/DEEP_ANALYSIS_HARNESS_ROADMAP.md` §14·§15.3)
**범위:** 재개 시점에 "이 스레드가 어떤 토폴로지로 멈췄는가" 를 복원한다
**선행 조건:** ✅ **SCHEMA1 (2026-08-25, `d9eaeeb5`).** G2 스펙 §8이 이 작업을 미룬
근거가 정확히 그것이었다 — "SCHEMA1을 안 고친 채 마이그레이션을 한 칸 더 쌓는 셈이다".
이 설계는 결국 마이그레이션을 쓰지 않지만(§3.1), 그 판단을 **비용이 아니라 설계로**
내릴 수 있게 된 것이 SCHEMA1이 닫힌 결과다.

> 📌 **트랙 A의 라이브 표본과 병행 가능하다.** G2 스펙과 같은 이유다 — 이 설계는
> 챗 경로의 그래프 결정과 재개만 건드리고 deep_analysis 의 LLM 호출 경로·프롬프트·
> 모델·토큰 한도를 건드리지 않는다. §10.2의 "측정 중 변경 금지" 에 걸리지 않는다.

## 1. 목적과 관문

**목적:** 설계된 run 이 승인 게이트에서 멈춰도 **같은 그래프로** 재개되게 한다.

**지금 무슨 일이 일어나는가.** `approval_handlers.py:130` 이
`multi_agent_workflow.graph` — **정적 컴파일 그래프** — 를 읽고 그 위에서
`aget_state` · `aupdate_state` · `astream(None)` 을 부른다. 설계된 그래프는
`_resolve_execution_graph` 가 만든 **호출 스코프의 ephemeral 객체**이며 어디에도
캐시되지 않는다(G2 스펙 §3.1의 "설계된 그래프는 캐시하지 않는다"). 체크포인트의
노드가 정적 그래프에 없거나 간선이 다르면 재개가 엉뚱한 경로로 가거나 실패한다.

**지금은 무엇으로 막고 있는가.** 2026-08-25 (`e8c1198e`) 에 우회로를 넣었다 —
게이트 노드가 토폴로지에 하나라도 있으면 컴파일 전에 정적으로 폴백한다. 안전하지만
**설계 경로가 승인 게이트가 필요한 질의를 영영 가져가지 못한다.** 이 설계는 그
우회로를 걷어내는 것이 목표다.

**관문:** 설계된 run 이 `mission_approval`/`execution_approval` 에서 멈춘 뒤
재개했을 때, **재개에 쓰인 그래프의 토폴로지 해시가 멈출 때의 것과 같다.**
그리고 복원할 수 없으면 **정적으로 재개하지 않는다.**

## 2. 이 설계가 방어하는 것

### 2.1 조용한 정적 재개가 원래 버그다

가장 나쁜 실패는 예외가 아니라 **성공처럼 보이는 재개**다. 정적 그래프로 재개하면
LangGraph 는 체크포인트의 채널을 읽고 자기 간선을 따라 계속 간다 — 사용자에게는
승인이 처리된 것으로 보이고, 실제로는 설계가 의도한 경로와 다른 파이프라인이 돈다.
§3.2가 이 저장소의 관통 주제로 적은 *"모든 실패가 성공처럼 보였다"* 의 재개 판이다.

**그래서 이 설계의 실패 처리는 전부 fail-closed 다** (§5).

### 2.2 계약은 재개 사이에 바뀔 수 있다

토폴로지는 우리 DB 에서 오므로 출처는 신뢰할 수 있다. 신뢰할 수 없는 것은
**시간**이다 — 멈춘 뒤 배포가 노드를 없애거나 `requires` 를 바꾸면 저장된
토폴로지는 더 이상 유효하지 않다.

그리고 `build_ephemeral_workflow` 는 **재검증하지 않는다.** 독스트링이 명시한다:
"`design_graph_or_fallback` 이 승인한 토폴로지만 이 함수에 들어온다는 전제 위에
서 있다 -- 이 함수 자신은 재검증하지 않는다." 그 전제는 **설계 직후에는 참이고
재개 시점에는 참이 아니다.** 그래서 재개 경로가 `validate_topology` 를 다시 돌린다
(§3.4). LLM 을 쓰지 않으므로 값싸다.

### 2.3 인스턴스 슬롯 금지는 여전히 유효하다

G2 스펙 §2.3이 못박은 것을 캐시 층에서 되살리지 않는다. `MultiAgentWorkflow` 는
오래 살고 요청 간 공유되므로 **설계된 그래프를 인스턴스에 두면 경쟁한다.**
재개는 캐시를 읽는 것이 아니라 **상태에서 읽어 다시 짓는다** — 워커가 여럿이어도
성립하는 유일한 모양이다.

## 3. 구성 요소

### 3.1 저장 위치 — `AgentState` (마이그레이션 0건)

세 후보를 놓고 골랐다.

| 안 | 마이그레이션 | 대가 |
|---|---|---|
| **A. `AgentState` 에 싣는다 (채택)** | 0 | 토폴로지가 모든 체크포인트에 복제된다 |
| B. 새 테이블 `workflow_thread_topologies` | 048 | **체크포인트와 수명이 갈린다** |
| C. `langgraph_checkpoints.metadata` | 0 | LangGraph 소유 필드에 우리 개념을 넣는다 |

**A 를 고른 결정적 이유는 수명이다.** G2 스펙 §8이 요구한 것은 "토폴로지를
체크포인트와 **같은 수명으로** 영속화" 였고, 상태에 실으면 그것이 저절로 성립한다 —
체크포인트가 지워지면 토폴로지도 함께 사라지고 그 반대도 없다. B 는 정합성을 손으로
관리해야 하며, 이 저장소에는 수명이 갈려서 아픈 전례가 이미 있다(SCHEMA2 —
`deep_analysis_runs` 는 events 트리거 때문에 삭제할 수 없다).

C 를 버린 이유는 소유권이다. `metadata` 에 우리가 이미 `new_versions` 를 넣고 있지만
(`checkpointer.py:293`), 그것은 **LangGraph 가 준 값을 되싣는 것**이고 우리 개념을
넣는 것과 다르다.

**대가를 정확히 적는다.** 토폴로지 JSON(노드 27 + 간선이면 2KB 남짓)이 체크포인트
**마다** 복제된다. 이것이 A 의 값이다 — 수명이 자동으로 같아지는 대신 중복을 받는다.
체크포인트 하나가 이미 상태 전체를 담고 있으므로 상대적 증가는 작다.

### 3.2 `AgentState.execution_topology`

```python
# neos/workflow/state.py
class AgentState(TypedDict):
    ...
    # 이 실행이 어떤 그래프로 돌고 있는가. 정적 실행이면 None.
    # 오케스트레이터만 쓴다 -- 어떤 노드도 읽지 않는다.
    execution_topology: NotRequired[dict[str, Any] | None]
```

**어떤 노드도 이 키를 읽지 않는다.** 읽는 순간 노드가 자기 그래프 모양에 따라
행동을 바꾸게 되고, 그것은 C1 계약(`reads`/`writes`)이 표현하려는 것과 정반대
방향의 결합이다. 작성자는 오케스트레이터 하나다 — 설계 §1의 P2("단일 작성자")를
상태 층에 같은 모양으로 적용한다.

> ⚠️ **§14.4의 정직성 지표를 확인할 것.** 카나리아는 *선언된* 키와 *추출된* 키를
> 비교한다. 이 키는 선언되지만 어떤 노드도 읽지 않으므로 "선언됐는데 아무도 안
> 읽는 키" 로 잡힐 수 있다. 구현 시 카나리아가 무엇이라 하는지 보고, 예외로
> 둘지 카나리아 쪽을 고칠지 정한다.

### 3.3 직렬화 — `topology.py` 의 왕복 한 쌍

```python
def topology_to_payload(topology: GraphTopology) -> dict[str, Any]: ...
def topology_from_payload(payload: Mapping[str, Any]) -> GraphTopology: ...
```

`GraphTopology` 는 frozen dataclass 이고 필드가 tuple·Mapping 이라 JSON 왕복에서
잃는 것은 **타입뿐**이다(tuple → list). `from_payload` 가 tuple 로 되돌린다.

**해시로 왕복을 검사한다.** `topology_hash(from_payload(to_payload(t))) ==
topology_hash(t)` 가 성립해야 한다 — 이것이 직렬화가 무손실임을 주장하는 가장 짧은
단언이고, 필드가 늘어나도 자동으로 따라온다(손으로 나열한 비교는 낡는다).

### 3.4 재개 경로 — 읽고, 재검증하고, 다시 짓는다

`approval_handlers.resume_with_decision` 이 하는 일이 넷으로 나뉜다.

1. **상태를 읽는다** — 지금처럼 정적 그래프로 `aget_state(config)`.

   > 🔴 **이것이 이 설계의 검증되지 않은 가정이고, 구현의 첫 태스크가 그것을
   > 재는 것이다.** 근거는 "체크포인터가 `thread_id` 로 조회하므로 어느 그래프
   > 객체로 읽어도 같은 데이터가 나온다" 이고, 지금 이 경로로 `pending_approvals`
   > 를 읽는 것은 사실이다 — **그러나 지금 읽는 것은 전부 정적 run 의
   > 체크포인트다.** 설계된 run 의 체크포인트를 **정적** 그래프로 읽는 것은 이
   > 저장소에서 한 번도 일어난 적이 없다. LangGraph 는 상태 채널 외에 노드별
   > 트리거 채널을 갖고, 노드 집합이 다르면 `aget_state` 가 무엇을 하는지
   > 확인된 바 없다.
   >
   > **가정이 깨지면 설계가 바뀐다** — 상태를 읽으려고 그래프가 필요한데 그래프를
   > 지으려고 상태가 필요한 닭-달걀이 되고, 그때는 체크포인터를 **직접** 조회해
   > 토폴로지만 꺼내는 경로(그래프를 거치지 않는 `aget_tuple`)로 간다.
   > `PostgreSQLCheckpointer` 는 자체 구현이라 그 경로를 열 수 있다.
   > 그래서 이것을 **1번 태스크로 두고, 결과에 따라 3.4를 고친다.**
2. **토폴로지를 꺼낸다** — `state.values.get("execution_topology")`.
   `None` 이면 정적 run 이므로 지금 동작 그대로다(정적 그래프로 재개).
3. **재검증한다** — `topology_from_payload` → `validate_topology(topology,
   NODE_CONTRACTS, ...)`. 위반이 하나라도 있으면 §5로 간다.
4. **다시 짓는다** — `build_ephemeral_workflow(multi_agent_workflow, topology,
   checkpointer=..., interrupt_before=<토폴로지에서 계산>)`. 그 그래프로
   `aupdate_state` · `astream(None)` 을 부른다.

`interrupt_before` 는 **저장하지 않고 다시 계산한다** — G2-d 가 정한 그대로
`set(topology.nodes) & _INTERRUPT_GATED_NODES` 다. 저장하면 게이트 정책이 바뀌었을 때
옛 목록으로 재개하게 되고, 계산하면 지금 정책을 따른다.

### 3.5 쓰는 곳 — `_resolve_execution_graph` 의 결과가 초기 상태로

`execute_workflow` 가 초기 상태를 만들 때 `ExecutionGraph` 가 설계된 것이면
`topology_to_payload` 를, 정적이면 `None` 을 싣는다. `ExecutionGraph` 는 이미
`source` 와 `topology_hash` 를 들고 다니므로(G2-c·G2-e) 그 값 객체에 원본
토폴로지를 하나 더 실어 나르는 것이 가장 작은 변경이다.

### 3.6 우회로 제거

`e8c1198e` 가 넣은 `approval_gate_in_designed_topology` 폴백을 걷어낸다. 같은
커밋이 "이 폴백을 걷어내면 `EphemeralApprovalGateUnsupported` 가 다시 살아난다" 고
적어 뒀으므로 그 분기도 함께 본다 — 그 예외는 **체크포인터 없이 게이트 노드를
컴파일할 때** 나므로, 챗 경로(`use_checkpointer=False`)에서는 여전히 유효한
방어다. 걷어내는 것은 게이트 폴백이지 그 예외 처리가 아니다.

## 4. 이벤트와 관측

새 kind 를 만들지 않는다. **FE 라벨 부채를 만들지 않기 위해서**이고(§5.2의 FE1 이
정확히 그 대가를 치렀다), 기존 `graph_design_fallback` 에 사유를 실어 구분한다.

| 상황 | 어디에 | 무엇이 |
|---|---|---|
| 설계된 run 이 같은 토폴로지로 재개됐다 | span 이벤트 | `topology_hash` — 멈출 때의 것과 대조 가능해야 한다 |
| 재검증이 위반을 냈다 | span 이벤트 + 로그 | 위반 목록. **어느 노드의 어느 규칙인지** |
| 토폴로지를 못 읽었다(직렬화 오류) | span 이벤트 + 로그 | 예외 타입과 메시지 |

**해시를 싣는 것이 이 설계의 관문 그 자체다.** 재개 이벤트의 `topology_hash` 가
`graph_design_accepted` 의 것과 같은지가 "같은 그래프로 재개됐는가" 의 유일한
기계 검증 가능한 답이다.

## 5. 에러 처리 — 전부 fail-closed

| 실패 | 반응 |
|---|---|
| `execution_topology` 가 있는데 역직렬화 실패 | **503**. 정적으로 재개하지 않는다 |
| 재검증이 위반을 냈다 | **503**. 위반 목록을 로그에 남긴다 |
| `build_ephemeral_workflow` 가 던진다 | **503** |
| `execution_topology` 가 `None` | 정적 재개 — **정상 경로다**(정적 run) |

**왜 503 인가.** 이 실패들은 전부 "서버가 이 스레드를 지금 재개할 수 없다" 이지
"요청이 틀렸다" 가 아니다. 그리고 **재시도가 의미 있다** — 계약을 되돌리는 배포가
나가면 같은 요청이 성공한다. 지금 코드가 초기화되지 않은 그래프에 대해 쓰는 것과
같은 코드다(`approval_handlers.py:124-128`).

**사용자가 승인을 잃는다는 점을 정직하게 적는다.** 재개할 수 없으면 그 run 은
사람이 손대기 전까지 멈춰 있다. 대안(정적 재개)은 §2.1이 적은 조용한 오실행이고,
그것보다는 멈춘 채 보이는 편이 낫다 — 트랙 E 가 `MANUAL_RECOVERY_REQUIRED` 에 대해
내린 것과 같은 판단이다.

## 6. 테스트 (TDD)

| # | 무엇을 고정하는가 |
|---|---|
| 1 | **직렬화 왕복이 해시를 보존한다** — `topology_hash(from(to(t))) == topology_hash(t)` |
| 2 | **설계된 run 은 자기 토폴로지를 상태에 남긴다**, 정적 run 은 `None` 을 남긴다 |
| 3 | **재개가 같은 토폴로지로 일어난다** — 재개에 쓰인 그래프의 노드 집합이 멈출 때의 것과 같다. ⚠️ `source`/`nodes` 라벨만 보는 단언은 이것을 지키지 못한다(G2 스펙 서두의 경고) — **컴파일된 그래프 자체**를 본다 |
| 4 | **계약이 바뀌면 거부한다** — 저장된 토폴로지의 노드를 `NODE_CONTRACTS` 에서 지우고 재개하면 503 이고 정적으로 흐르지 않는다 |
| 5 | **정적 run 의 재개는 달라지지 않는다** — 회귀 가드 |
| 6 | **게이트가 있는 설계가 이제 컴파일된다** — §3.6 우회로가 걷혔다는 것을 행동으로 고정. 지금 있는 `test_an_approval_gate_falls_back_even_when_a_checkpointer_exists` 는 이 태스크에서 **기대가 다시 뒤집힌다** |

## 7. 하지 않는 것

- **설계된 그래프를 캐시하지 않는다** — §2.3. 상태에서 다시 짓는다
- **`interrupt_before` 를 저장하지 않는다** — §3.4. 지금 정책으로 다시 계산한다
- **새 이벤트 kind 를 만들지 않는다** — §4
- **기존 체크포인트를 마이그레이션하지 않는다** — 이미 멈춰 있는 run 은
  `execution_topology` 가 없어 `None` 으로 읽히고 정적 재개된다. 지금과 같은
  동작이며, 플래그가 꺼져 있어 설계된 run 자체가 아직 없다
- **`build_ephemeral_workflow` 안에 재검증을 넣지 않는다** — 그 함수의 전제는
  설계 직후 경로에서는 여전히 옳다. 재검증은 **재개 경로가** 한다(§2.2)

## 8. 미결로 남기는 것

### 상태 크기는 재지 않았다

토폴로지 2KB × 체크포인트 수라는 계산은 했지만 **실측하지 않았다.** 설계된 run 이
아직 없어 잴 대상이 없다. 플래그를 켜면 `langgraph_checkpoints` 의 행 크기를 정적
run 과 비교해 볼 것.

### 이 설계는 `graph_design_enabled` 를 켜지 않는다

켜는 것은 별도 결정이며 그 관문은 로드맵 §15.3 이 든다. 이 설계가 닫는 것은 그
셋 중 하나(승인 재개)뿐이다. 그리고 설계자 통과율 75% 는 `must_write` 수정
**이전에** 잰 수이므로, 켜기 전에 새 사전 등록으로 다시 재야 한다(§13.5).
