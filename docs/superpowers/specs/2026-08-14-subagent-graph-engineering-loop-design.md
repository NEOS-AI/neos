## 1. 이 기능을 막고 있는 것 — 먼저 읽을 것

**노드 간 계약이 전부 암묵적이다.** 실측(2026-08-14):

- `AgentState`는 `TypedDict`이고 필드가 **100개**다 (`neos/workflow/state.py:44`)
- 노드 의존 선언이 **어디에도 없다** — `requires` · `depends_on` · `precondition` · `REQUIRED_KEYS` 전부 0건
- 노드는 `state.get(...)` / `state[...]`로 **90곳**에서 읽는다

즉 `_integrate_results_node`가 `state.get("search_results")`를 읽을 때, 검색 노드가 먼저 돌았다는 것은 **`_build_workflow()`의 배선 순서에만** 존재하는 약속이다. 코드 어디에도 적혀 있지 않다.

**서브에이전트에게 배선 권한을 주면 이 약속이 깨진다.** 그리고 깨져도 예외가 나지 않는다 —
`state.get()`이 기본값(`None`/`[]`)을 돌려주고, 노드는 **그럴듯하지만 빈 산출물**을 낸다.

> 이것은 로드맵 §3.2가 이 시스템의 관통 주제로 적은 것과 정확히 같다:
> *"이 시스템의 모든 실패가 성공처럼 보였다. … 전부 조용히 degrade했고 원장에는 성공과
> 구별되지 않는 흔적만 남았다."*
> 계약을 명시화하지 않은 채 서브에이전트를 붙이면, 그 실패 모드를 **생성하는 기계**를 붙이는 셈이다.

**따라서 이 기능의 첫 작업은 서브에이전트가 아니라 계약 명시화다.** 그리고 그 작업은
서브에이전트 루프를 영영 만들지 않아도 값어치가 있다 — 지금 손으로 쓴 그래프의 순서
버그도 같은 검사기가 잡는다.

## 2. 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| **G-D1** | 서브에이전트는 **기존 노드의 조합·배선만** 바꾼다. 노드 코드는 생성하지 않는다 | 노드 25개는 손으로 쓴 신뢰된 코드다. 코드 생성은 트랙 E(코딩 에이전트)와 범위가 겹치고 샌드박스가 필요하다 |
| **G-D2** | 토폴로지는 **ephemeral**이다 — 이번 질의에만 살고 버려진다 | 영속화는 승격·롤백·버전 관리를 함께 요구한다. 먼저 ephemeral로 가치를 증명한다 |
| **G-D3** | **기본은 정적 그래프.** 설계 서브에이전트는 명시적으로 요청됐을 때만 돈다 | 매 질의 LLM 설계는 지연·비용·비결정성을 늘린다. §4.2가 *"요청마다 LLM으로 난이도 분류 금지"*로 같은 실수를 이미 기각했다 |
| **G-D4** | **C1·C2가 C3보다 먼저 완성돼야 한다** | 순서를 바꾸면 검증 없는 LLM 배선이 프로덕션에 들어간다 |
| **G-D5** | 모든 폴백은 **원장 이벤트를 남긴다** | §3.2: *"새 fallback을 추가하려면 그 fallback이 남기는 이벤트를 함께 정의한다"* |

## 3. 컴포넌트

의존 순서대로 넷이다. 앞의 둘은 단독으로도 값어치가 있다.

| # | 컴포넌트 | 하는 일 | 단독 가치 |
|---|---|---|---|
| **C1** | 노드 계약 선언 | 노드별 `reads` / `writes` / `requires`를 데이터로 선언 | ✅ 손으로 쓴 그래프의 순서 버그도 잡는다 |
| **C2** | 토폴로지 검증기 | 제안된 그래프를 계약에 비춰 검사 | ✅ 정적 그래프의 회귀 가드가 된다 |
| **C3** | 설계 서브에이전트 | 질의를 보고 노드 부분집합과 배선을 **제안** | — |
| **C4** | ephemeral 실행 + 원장 | 통과 시 실행, 아니면 폴백 — 둘 다 기록 | — |

### 3.1 C1 — 노드 계약

각 노드에 선언을 붙인다. 검증기가 읽어야 하므로 **코드가 아니라 데이터**로 둔다.

```python
@node_contract(
    reads=("query", "conversation_context"),
    writes=("search_results", "search_cost_micros"),
    requires=("query_classified",),
)
def _orchestrate_search_node(self, state): ...
```

**`reads`와 `requires`는 다르다.**
`reads`는 "이 키를 읽는다"이고, `requires`는 **"이 키가 없으면 이 노드의 실행은 무의미하다"**이다.
`state.get()`이 기본값을 돌려줘 조용히 통과하던 자리가 `requires`에서 드러난다.

**계약은 실측으로 채운다.** 25개 노드의 `state.get(...)` · `state[...]` · 반환 dict 키를
실제로 읽어 뽑는다. 추측으로 채우면 검증기가 검증하는 대상이 허구가 된다.

### 3.2 C2 — 토폴로지 검증기

| 규칙 | 거부 사유 |
|---|---|
| 도달성 | START에서 못 닿는 노드 / END에 못 닿는 경로 |
| 종료성 | 반복 상한이 없는 사이클 |
| **계약 충족** | 노드의 `requires` 키를 **선행 노드 중 누구도 `writes`하지 않는** 경우 |
| 필수 노드 | 응답 생성 노드 부재. 사실성 질의인데 검증 노드 부재 |
| 예산 | 노드별 비용 상한의 합이 질의 예산을 초과 |

**계약 충족 검사가 이 기능의 존재 이유다.** 나머지 넷은 부수적이다.

검증기는 **정적 그래프에도 적용한다.** 지금 손으로 쓴 배선이 자기 계약을 만족하는지 먼저
증명해야 하고, 만족하지 못하는 곳이 나오면 그것은 이 기능이 찾아낸 기존 버그다.

### 3.3 C3 — 설계 서브에이전트

입력: 노드 카탈로그(계약 포함) + 질의 + 예산.
출력: **토폴로지만** — 노드 부분집합과 엣지 목록. 코드는 못 쓴다.

**트리거는 명시적 요청뿐이다** (기능 플래그 + 질의 옵션). 자동 트리거는 범위 밖이다 —
"어떤 질의가 커스텀 그래프를 필요로 하는가"를 LLM에게 매번 묻는 것이 바로 §4.2가 기각한 구조다.

### 3.4 C4 — ephemeral 실행과 원장

| 이벤트 | 언제 | 페이로드 |
|---|---|---|
| `graph_design_requested` | 설계 서브에이전트 호출 | 질의 유형, 예산 |
| `graph_design_rejected` | 검증 실패 | **위반한 규칙과 노드를 함께** |
| `graph_design_accepted` | 검증 통과 | 토폴로지 해시, 노드 목록 |
| `graph_design_fallback` | 정적 그래프로 되돌아감 | 사유 |

폴백은 **조용히 일어나지 않는다.** 그리고 실행 후 그 run이 정적 경로 대비 어땠는지 비교
가능해야 한다 — 토폴로지 해시가 그 조인 키다.

## 4. 실패 처리

| 실패 | 처리 |
|---|---|
| 설계 서브에이전트 호출 실패·타임아웃 | 정적 그래프로 폴백 + `graph_design_fallback` |
| 검증 실패 | 정적 그래프로 폴백 + `graph_design_rejected`(규칙·노드 포함) |
| 설계된 그래프 실행 중 노드 예외 | **재설계하지 않는다.** 기존 그래프의 예외 처리와 동일하게 다룬다 |

**재설계 루프를 만들지 않는다.** 실패한 토폴로지를 서브에이전트에게 돌려주어 고치게 하면
질의 하나가 LLM 설계를 여러 번 태우고, 지연이 비결정적으로 늘어난다. 한 번 제안하고,
통과하면 쓰고, 아니면 정적 경로로 간다.

## 5. 테스트

| 계층 | 무엇을 |
|---|---|
| C1 | 각 노드의 선언이 실제 `state` 접근과 일치하는지 — 소스에서 키를 뽑아 대조 |
| C2 | 규칙별 거부 케이스 + **정적 그래프가 자기 계약을 만족한다는 회귀 가드** |
| C3 | 결정론적 fake 서브에이전트로 토폴로지 계약(형식·노드명 유효성)을 고정 |
| C4 | 폴백 4경로가 각각 지정된 이벤트를 남기는지 |

C2의 "정적 그래프 회귀 가드"가 가장 값어치가 높다 — 서브에이전트가 없어도 계속 일한다.

## 6. D3b와의 관계

`docs/DEEP_ANALYSIS_HARNESS_ROADMAP.md` §11.3의 **D3b는 langgraph 런타임 교체**다.
C2는 그래프 표현 위에 서 있으므로 **D3b가 끝나면 다시 써야 한다.**

→ 이 기능은 **D3b 착수 전에 끝내거나, D3b 이후에 시작한다. 동시 진행은 피한다.**
C1(노드 계약)은 런타임과 무관하므로 어느 쪽이든 살아남는다.

---

## 7. 완료의 정의

1. 25개 노드 전부가 계약을 선언한다
2. 검증기가 다섯 규칙을 구현하고, **정적 그래프가 그 검증을 통과한다**
3. 설계 서브에이전트가 기능 플래그 뒤에 있고 기본은 꺼져 있다
4. 폴백 4경로가 각각 원장 이벤트를 남기고, 그 이벤트가 사유를 싣는다
5. 토폴로지 해시로 설계된 run과 정적 run을 비교할 수 있다
