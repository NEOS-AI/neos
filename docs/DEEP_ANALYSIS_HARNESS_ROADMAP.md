## 2. 북극성과 출하 기준

### 2.1 목표 상태

> **검증형 분석(deep_analysis loop)을 NEOS의 1차 실행 모델로 승격한다.**
> 사용자가 "이 주장이 사실인가"를 물으면, 모든 문장이 검증된 클레임으로 역추적되는
> LLM 작성 리포트가 나온다. 실패하면 조용히 degrade하지 않고 원장에 이유를 남긴다.
>
> **그리고 그 하네스는 고정된 구조가 아니라 조립된 구조다.** 부품은 전부 교체 가능한
> 플러그인이되 — **무엇이 조립됐는지는 언제나 원장이 답한다.** 구성이 고정돼서 측정이
> 성립하는 것이 아니라 **구성이 복원 가능해서** 성립한다.

### 2.2 출하 기준 S1~S6 — 전부 ✅ (2026-08-18). 그러나 출하 신호가 아니다

| # | 기준 | 근거 |
|---|---|---|
| S1 | LLM이 조립한 리포트가 실제로 나온다 | 표본 #1, `synth_pass` 0 → 18 |
| S2 | 게이트가 알맹이 있는 리포트를 통과시킨다 | 표본 #5, **n=1** ⚠️ |
| S3 | 리포트 본문이 보존된다 | 전제 정정 — 유실된 적 없었다 |
| S4 | 정지 사유가 원장에서 정확히 구분된다 | 표본 5회 연속 무이벤트 정지 0건 |
| S5 | 전체 스위트가 CI에서 결정론적으로 통과 | 시드 5종(1·2·3·7·12345) 실측 + **벽시계 상한 6분** |
| S6 | 실패가 사용자에게도 보인다 | fixture가 **기계로** 라벨 커버리지를 센다 |

> 🔴 **6/6은 "출하하라"가 아니다.** 이 여섯은 **조용한 실패**를 막으려고 쓴 기준이지
> **조사 품질**을 증명하려고 쓴 것이 아니다.
>
> **W6(승격)의 실제 관문은 둘이다:**
> 1. **리덕션 층** — 아래 §3의 사슬. (원래 "조사 깊이"였다가 표본 #21이 반증,
>    "리포트 층"으로 옮겼다가 D91이 다시 반증했다)
> 2. `docs/ROADMAP.md`의 **R1·R2·R6**
>
> **S2가 n=1이라는 것도 같이 읽어야 한다** — #20은 통과 1건, #21은 **0건**이다.
> 승격 전에 S2를 다시 두껍게 세우는 것은 선택지가 아니라 필수에 가깝다.

### 2.3 S5의 측정 방법 — "3회 연속 초록"은 근거가 아니다

순서 의존 실패는 시드의 함수라서, 세 번 초록은 "결정론적이다"가 아니라
**"세 시드가 지뢰를 밟지 않았다"**는 뜻일 수 있다. 실제로 결함이 둘 있었다
(전역 싱글턴 오염 · 전역 asyncio 패치로 인한 **10시간 46분 멈춤**).

- 시드를 명시하고 기록한다 (`--randomly-seed=N`)
- **벽시계 상한을 건다** — 정상 2분인 스위트가 6분을 넘기면 실패로 센다
- **멈춤은 실패보다 나쁘다** — `pytest`는 그것을 세지 않는다

**하네스 층 (전부 다치고 나서 세운 것):**

- **P2 단일 작성자** — 원장 쓰기는 오케스트레이터 한 곳
- **judge ≠ worker** — 자기 승인 편향 방지. ✅ 지켜지고 있다(`judge: claude-opus-4-8`).
  ⚠️ 다만 워커와 **같은 가족**이라 편향 분리가 약하다 — 유효한 OpenAI 키가 생기면 재검토
- **append-only 이벤트 로그** — UPDATE/DELETE 금지. 예외는 의도를 표명한 트랜잭션뿐
  (`Ledger.purge_run()` + `SET LOCAL`)
- **매직넘버 금지** — 전부 settings. 프롬프트는 전부 파일

**플러그인 층 (다치기 전에 세우는 것):**

- **플러그인은 원장의 작성자가 될 수 없다** (P2의 확장)
- **동적 설치 플러그인도 `TokenBudget.reserve()`를 거친다** — 회계 밖 호출은 floor 산식을
  **조용히** 깬다. 가격 없는 모델이 비용을 0으로 집계하는 것과 **같은 고장 유형**
- **매니페스트 없는 런은 표본이 아니다** — 지침이 아니라 기계가 거부한다
- **judge 플러그인과 worker 플러그인은 같은 인스턴스일 수 없다** — E3의 재발 방지

**추가로 하지 않기로 한 것:**

- **계약을 고쳐서 위반을 없애기** — `.get()` 기본값을 더해 `requires`를 떨어뜨리면
  검증기는 초록이 되고 **사용자가 보는 버그는 그대로다**
- **새 fallback을 이벤트 없이 추가하기** — fallback을 더하려면 그것이 남기는 이벤트를 함께 정의한다
- **"동적이니까 설정이 아니다"** — 매직넘버 금지는 플러그인 안에서도 유효하다

### I. 서브에이전트 노드 그래프  <sub>신규, 2026-09-14</sub>

**설계 정본:** [GRAPH_SUBAGENT_INTEGRATION_DESIGN.md](GRAPH_SUBAGENT_INTEGRATION_DESIGN.md) (§13 코드 대조 리뷰 반영).
**결정:** K25′ — 사용자 승인 2026-09-14, `PARENT_MEDIATED_COLLABORATION_DESIGN.md` K25 행 · `DECISIONS.md` D97.
**코드:** `neos/workflow/subagent_nodes.py` · `topology.py` 규칙 셋 · 마이그레이션 **058**(057은 병행 작업용으로 비움).

- **Approach W 는 여전히 기각.** 노드는 도구로 남고, 자식 정체성은 **실행 스코프**(`wf_…`)가 갖는다 —
  대화 스레드는 턴마다 재사용되므로 `thread_id` 를 부모로 쓰면 둘째 턴이 첫 턴 자식을 되찾는다
- **1-step 법.** 노드 한 번 = `advance` 한 번. 계속은 빌더가 붙인 자기 루프이고, 걸음 상한은
  `max_turns` 가 아니라 **`2·max_turns + 1`**(한 걸음 = 모델 턴 XOR 도구 배치) — **핸들러가 강제한다**
  (`loop_bounds` 값은 LangGraph 에 전달되지 않는다)
- **체크포인터 없는 경로에서는 조립하지 않는다.** 챗은 체크포인터가 **있다** — 폴백하는 곳은 A2UI 폼 제출뿐
- **보고는 unverified 검색 결과다.** `subagent_reports` 만으로는 읽는 노드가 없어 응답에 닿지 않았다.
  `fact_check` 를 거치지 않는 경로를 규칙이 거부한다
- **병렬 가지.** LangGraph 1.2 는 리듀서 없는 키의 동시 쓰기를 **조용히 덮지 않고 run 을 죽인다**.
  길이가 다른 가지의 조인은 두 번 돈다 — 조인은 `defer` 로 조립한다(변이 테스트로 확인)

| 단계 | 상태 | 남은 것 |
|---|---|---|
| GS4 · GS5 | ✅ | — (조인 `defer`·세마포어·스코프 취소는 GS2 코드, 라벨 짝은 양방향 테스트) |
| **GS3** | 🟡 **어휘만** — 플래그 켜면 카탈로그에 템플릿 줄. 꺼져 있으면 프롬프트 바이트 동일(테스트) | 프롬프트 v3 는 **M-1 사전 등록과 함께**. 한 표본에 카탈로그 확장과 문구 변경을 같이 넣지 않는다 |
| **GS6** | 🔴 표본 전 | M-0(사전 등록 완료) → M-1 사전 등록 → 표본. 켜는 것은 그 판정 뒤 |

> ⚠️ **리뷰가 찾은 기존 결함(범위 밖):** 템플릿 없는 설계도 병렬 가지가 리듀서 없는 키를 같이 쓰면
> run 이 죽는다. 새 규칙은 템플릿이 있을 때만 돈다 — 넓히면 M-0 비교가 끊기므로 별도 사전 등록이다.

## 9. 컨텍스트 엔지니어링 정책  <sub>전임본 §16</sub>

> **한 줄:** 새 모델 세대는 제약을 줄이고 판단에 맡기라고 말한다. 이 저장소에서 그 말은
> **프롬프트를 편집해도 된다는 허가가 아니라, 표본 한 건을 쓰라는 요구**다.

| # | 규칙 | 이 저장소의 흉터 |
|---|---|---|
| ① | 제약 → 판단 | `final_compose.md` v2·v3·v5가 표본 판정의 퇴적층 |
| ② | 예시 → 인터페이스 설계 | `node_summary.md`의 JSON 예시 리터럴 → H2 계약이 저장소 판본 |
| ③ | 선행 적재 → 점진 공개 | **스타일이 아니라 예산 레버다** — 강등 152건 전부 `input_bound` |
| ④ | 반복 → 정밀 | `[C:claimid]` 지시가 요약·조립·채점기 **세 겹**. D91이 좁힌 바로 그 구간 |
| ⑤ | 수동 → 자동 메모리 | **채택하지 않는다** — 대응물이 없다 |
| ⑥ | 단순 스펙 → 풍부한 참조 | F1의 사망 원인과 같은 진단 |

**①~④는 서로 독립이 아니다** — 같은 자리를 가리킨다. **그래서 더 위험하다:**
한 표본에 셋을 같이 넣으면 "여러 변경을 한 표본에"를 정면으로 어긴다. **규칙 하나 = 표본 하나.**

> **역설 하나:** 규칙 ①은 "과잉 제약을 줄이라"인데 이 절은 그 적용에 **새 제약을 건다.**
> 모순이 아니다 — ①이 줄이라는 것은 *모델에게 주는 지시*이고 여기서 거는 것은
> *사람이 측정하는 절차*다. 후자를 풀면 전자의 효과를 **잴 수 없게 된다.**

**`final_compose.md` 계보(복원 완료):** v1의 규칙 넷은 **설계 시점**이고, 표본이 붙인 것은
v2(맹목 재굴림 방지) · v3(주지도 않은 질문 텍스트 요구) · v5(길지만 나쁘게 쓰는 재시도) **셋뿐**이다.
**셋 다 되돌리면 아픈 흉터다** — 그러나 그것이 CE1을 취소할 근거는 아니다.
이 표가 준 것은 **무엇을 되돌리는지 알고 되돌리는 상태**다.

## 10. 이 루프가 자기 자신에게서 배운 것

이 문서 전체를 관통하는 규율이다. 각 항목이 어느 표본에서 나왔는지는 `DECISIONS.md`에 있다
(전임본 §8.1.2가 표본 번호와 함께 적었다).

- **계측을 먼저 의심한다.** 자가 지표가 세 번 틀렸다. **루프는 틀린 지표에 성실하게 수렴한다.**
- **계측기가 도는지 보는 것은 통과를 보는 게 아니라 실패해야 할 때 실패하는지 보는 것이다.**
  `after <= before` 불변식은 **버그를 되살려도 통과했다**(양쪽이 0이라 공허하게 성립).
- **무는지 보지 않고 세운 게이트는 없느니만 못하다.** 게이트를 세울 때는 변이로 확인한다.
- **지표 정의가 바뀌면 키 이름을 바꾼다.** 유지하면 옛 표본의 값과 조용히 섞인다.
- **표본 없이 답할 수 있는 질문이 자주 있다.** D34·D38·D75·D87·D90·D91·D92가 전부 그랬다.
- **모르면 다음 수는 고치는 것이 아니라 재는 것이다.**
- **고침은 한 호출부에만 도착한다 — 사본을 먼저 세라.** ai-elements 29파일 · WORKSPACE1 아홉 곳 ·
  PREFLIGHT2 둘째 호출부 · `_safe_url`. "Mirrors …" 독스트링은 보증이 아니라 **신고**다.
- **유령 백로그가 우선순위 판단을 왜곡한다.** 종결 항목이 표에 남아 있으면 다음 사람이
  남은 일의 양을 과대평가한다. **문서가 코드보다 늦게 낡는 대가를 이 문서는 여러 번 치렀다** —
  E3는 종결 일주일 뒤까지 "지금 깨져 있다"로 남아 있었다.
- **둘을 구별하는 유일한 방법은 코드를 여는 것이다.**
- **측정이 도는 동안 대상을 바꾸지 말 것. 테스트 스위트도 측정이다.**
