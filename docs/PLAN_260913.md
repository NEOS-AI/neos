## 5. 스트림 B — Phase 5 Managed sandbox

### B2. 코딩 `SandboxProvider` ×2 — OPEN (원문 요지, 게이트는 원문 그대로)

- **대상:** E2B + Modal의 bounded prototype만. 공급자별 낮은 sandbox/exec/lifetime/cost cap과 opt-in 실계정 smoke를 사용한다.
- **계약:** `neos/coding/sandbox/base.py` 전면 (lifecycle/file/search/git/command/snapshot/PTY/watcher).
- **재사용:** `paths.py`, `ignore.py`. implement worktree는 **호스트 git만**. managed implement는 `policy_worktree_unavailable`.
- **하지 말 것:** `managed/adapters` 할당 프로토콜 재작성. vendor SDK를 코딩 루프에 직접 흩뿌리기. 호스트 PATH/HOME 복사.
- **필수 구조:** 좁은 provider client + immutable guest `neos-sandboxd` + durable NEOS ledger. 등록된 named profile만 받고 unsupported profile은 거절한다. network default-deny, deterministic owner/generation, revision/CAS, process-group/output cap, PTY/watcher journal, portable export를 공통 계약으로 둔다.
- **hard gap:** E2B/Modal 공개 API에는 NEOS `pids`와 workspace byte quota를 hard-enforce하는 계약이 확인되지 않았다. 해당 보장이 필요한 profile은 fail closed하며 helper guard를 vendor hard boundary라고 부르지 않는다.
- **완료 gate:** 기존 conformance + security + recovery suite가 두 provider에서 통과하고 opt-in 실계정 smoke, 비용/cleanup SLO, region/residency, credential/image provenance 보안 검토를 통과해야 한다. factory가 이름을 받아도 기본 profile은 여전히 `memory/off`; production enable은 별도 승인이다. 게이트 항목의 정본은 [재검토 §8.2](MANAGED_SANDBOX_PROVIDER_REVIEW_260914.md).
- **들어간 것 (2026-09-15~):** 관리형 할당 평면 위의 코딩 provider · `neos/coding/sandboxd/` guest 모듈 · 코딩 runtime ledger(마이그레이션 057) · HMAC ownership digest · `coding_run_leases` 실행 lease fence · named profile `offline-v1` · E2B/Modal 좁은 client 와 fake SDK. conformance·security·recovery 는 **두 fake 에서** 통과. 설계 메모: [MANAGED_SANDBOX_B2_DESIGN_260915.md](MANAGED_SANDBOX_B2_DESIGN_260915.md)
- **남은 것:** 실 SDK binding · 실계정 opt-in smoke·비용 ceiling(gate 4) · region/residency(gate 5) · 보안 검토(gate 7) · 실계정에서 gate 1–3 재실행 · region outage · portable export · 런타임 배선(admission 직후 `prepare_coding_intent`, 백엔드 주입) · guest journal 영속화 · sandboxd 이미지 digest 발행. 이것이 트랙 Q14c(관리형 브라우저)·Q6c(관리형 비밀 채널)·J 의 production 샌드박스·E-S2 의 staging/production 을 연다
- **gate는 통과하지 않았다.**

- **B3. 관측·장애·용량 — OPEN.** outage 시 신규 task 차단, 기존 task 표면화. exec slot + idle+timeout grace. cleanup SLO, error budget, exit plan
- **B4. Allowlist canary — OPEN.** allowlisted org/repo 만. security review
- **B5. Fail-closed sandbox 요구 — CLOSED.** 메모리/호스트 폴백 없음
