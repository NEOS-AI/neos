## 0. 한 장 요약

NEOS는 이미 **durable coding 런타임**(lease, checkpoint, sandbox, 승인 이벤트)과 **OpenClaw 스타일 채널 골격**(Slack/Discord/Telegram → `ChannelGateway` → LangGraph)과 **연구용 메모리/스킬 로더**를 갖고 있다. 부족한 것은 엔진이 아니라 **에이전트 계약**이다.

| 축 | 이미 있는 것 | 없는 것 (이번 계획) |
|---|---|---|
| 코딩 루프 | 1-step durable iterator, Celery, 이벤트 로그 | 병렬 RO, 합성 tool_result, 실제 Stop, LLM compact, 훅 포트 |
| 코딩 툴 | 9개 (`read/search/git/write/execute`) + argv 격리 | Edit, Read offset, Todo, 툴 역할 분리, 승인 경고 |
| 코딩 프롬프트 | `"Work safely…"` 한 줄 (`runtime.py:516`) | 섹션형 시스템 프롬프트, 검증/정직 계약, `AGENTS.md` |
| 원격 호출 | Socket Mode 어댑터 3종 + circuit breaker | mention/allowlist, 스레드 세션, busy lock, 채팅 승인, `/code` |
| 자기개선 | `MemoryManager.learn()` API, 에피소드 저장, Beat | writer 0건, 코딩 교훈, curator, 세션 검색 도구 |

가장 싼 품질 향상은 **프롬프트 조립 + Edit 툴 + 채널 안전 게이트**다. 가장 위험한 실수는 Hermes식 fail-open 학습을 프로덕션 스킬에 켜거나, 모든 Slack 메시지를 coding task로 보내는 것이다.

## 2. 가져올 것 / 가져오지 말 것

### 2.1 Claude Code에서 가져올 계약

1. **루프는 “도구가 있는 한 돈다”가 아니라 “safe-point마다 재개되는 배치 기계”로 남긴다.** CC의 `while(true)`를 이식하지 않는다. `partitionToolCalls`의 **연속 READ_ONLY 병렬 / mutate 직렬**만 가져온다.
2. **미완료 tool_use에는 반드시 합성 error result.** abort/lease 상실 후 resume이 깨지지 않게.
3. **툴 계약:** Edit(정확 치환 + 사전 Read), Read offset/limit, Grep/Glob 역할 분리, TodoWrite, “전용 툴 우선·셸 최후”.
4. **프롬프트 계약:** 읽고 수정, 범위 준수, 실행으로 검증, 정직 보고, 비가역은 확인, 거부된 호출 재시도 금지. **NEOS 문구로 다시 쓴다.**
5. **점진적 스킬 공개:** 이름/한 줄만 노출, 본문은 invoke 시. 채팅 스킬과 trust zone 분리.
6. **페이즈 계약 (서브에이전트 런타임보다 먼저):** explore=쓰기 숨김, implement=전체, verify=쓰기 차단 + 구조화 보고.

### 2.2 Hermes에서 가져올 계약

1. **게이트 순서:** ignored → mention → allowlist → session bind → busy/lease → turn.
2. **스레드 = 세션.** 응답은 그 스레드에 고정.
3. **채팅 = 기본적으로 연구 워크플로.** 코딩은 명시적 `/code` 만.
4. **학습은 “모델이 자기 대화를 읽고 파일을 쓰는” 루프를 기본 ON으로 복제하지 않는다.** 가져올 것은 `_DO_NOT_CAPTURE_BLOCK`(미검증 실패를 규칙화 금지), read-before-write, 결정론적 prune, 스테이징+승인.
5. **README 과장 걸러내기:** session_search는 FTS이지 LLM 요약이 아니다. Honcho·LLM curator·write_approval OFF는 기본값이 아니다 / 켜면 안 된다.

### 2.3 명시적 비목표

| 출처 | 가져오지 않는 것 | 이유 |
|---|---|---|
| CC | TUI/Ink, bridge 자식 CLI, coordinator/team, Tungsten/Kairos, 자유 셸 문자열, 호스트 worktree | NEOS는 durable+sandbox. Phase 1 비목표와 충돌 |
| CC | 시스템 프롬프트 전문, `CYBER_RISK_INSTRUCTION`, ant-only 분기 | 유출/브랜드/내부 정책 |
| Hermes | WhatsApp 등 플랫폼 폭주, voice/TTS, pairing 전체, `state.db` 통째, ChannelGateway 교체 | 이미 OpenClaw 골격이 있음 |
| Hermes | Honcho, 펫/성격, `skill.py` 자동 생성, 인라인 셸 전처리, fail-open review + 승인 OFF | 멀티테넌트 포이즈닝 |
| 공통 | LangGraph를 coding loop로 승격, 챗 `search_tools`/research skills를 코딩 레지스트리에 등록 | trust boundary |

## 3. 목표 아키텍처

```
[Slack / Discord / Telegram]
        │  mention + allowlist + thread session
        ▼
ChannelRouter                         ← 신규 (얇은 분기만)
  ├─ 기본 텍스트 ──► ChannelGateway ──► MultiAgentWorkflow
  │                      │
  │                      ├─ approval button → approval_handlers
  │                      └─ /stop /status (워크플로)
  │
  └─ /code · !code ──► CodingTaskService   ← 기존 API, in-process
                           │
                           ▼
                     CodingLoop (durable 1-step)
                       ├─ prompts.builder          ← 신규
                       ├─ tools.orchestrator       ← 신규 (RO 병렬)
                       ├─ edit_file / todo_write   ← 신규
                       ├─ synthetic tool_result    ← 신규
                       └─ compact / hooks port     ← 신규
                           │
                           ▼  (런 종료, 승인 후)
                     Lesson stager → Beat curator
                     MemoryManager.learn()         ← 기존 API 배선
```

결정 세 가지:

1. **코딩 루프는 `chat_stream_pipeline` / `ChannelGateway._run_workflow`에 넣지 않는다.** `NEOS_CODING.md` §3.3을 유지한다.
2. **학습 아티팩트는 `org/user/workspace` 스코프.** `neos/skills/builtin`과 레포 `skills/`는 불변.
3. **툴 이름을 프롬프트 작업 전에 고정한다.** 설계 문서의 `list_files`/`grep`/`apply_patch`와 구현의 `*.v1`이 어긋나 있다. 이번 계획의 정규 이름:

## 4. 페이즈

각 페이즈는 독립 머지 가능해야 한다. 피처 플래그로 끈다. 완료 조건이 테스트로 닫히지 않으면 다음 페이즈로 가지 않는다.

### Phase 0 — 안전 게이트 (채널) · 예상 3–5일

채널이 열려 있으면 **길드/워크스페이스의 모든 메시지가 서비스 계정으로 워크플로를 탄다.** 기능을 더하기 전에 구멍을 막는다.

- `neos/api/channels/authz.py`: env CSV allowlist, 기본 fail-closed.
- Slack/Discord/Telegram 공통: mention 게이트(기본 ON, DM만 면제), ignored/allowed 채널, self/bot 루프 차단.
- `tests/api/channels/` 신설. 지금 채널 어댑터 테스트는 0건이다.
- 설정 키는 기존 `CHANNEL_*` 네임스페이스에 추가 (`docs/NEOS_OPENCLAW.md` 패턴).

완료 (2026-09-11): `neos/api/channels/authz.py` + 세 어댑터 `_handle_message`가 dispatch 전에 게이트한다. `tests/api/channels/` 공유 픽스처로 세 어댑터 각 7케이스 + authz 17케이스. 멘션 없는 채널 메시지·allowlist 밖·빈 allowlist는 워크플로를 호출하지 않고 침묵한다.

### Phase 1 — 코딩 에이전트가 “에이전트처럼” 말하기 · 예상 1–2주

가장 싼 품질 향상. 루프 계약을 거의 건드리지 않는다.

1. `neos/coding/prompts/` — `build_coding_system_prompt(tools, env) -> str`.
   섹션: Intro / System / Tasks / Actions / Tools / Tone.
   `runtime.py:516` 하드코딩 제거. 테스트가 빌더를 강제.
2. 툴 description을 X vs Y + 실패 시 행동으로 교체. schema 변경 없음.
3. `read_file.v1`에 offset/limit + 줄번호 규약.
4. `edit_file.v1` (정확 치환, 유일하지 않으면 실패, 세션 내 사전 Read 강제).
5. `write_file.v1` 사전 Read 계약.
6. 행동 계약 6줄: 읽고 수정 / 범위 / 전용 툴 / 검증 / 정직 / 비가역 확인.

완료 (2026-09-11): `build_coding_system_prompt`가 runtime 시스템 프롬프트를 조립한다. `edit_file.v1` + `read_file` offset/limit + 기존 파일 pre-read. 툴 description이 search vs execute를 가르친다. `tests/coding/prompts` + tools + 루프 슬라이스 회귀 통과.

의존: 없음. Phase 0과 병렬 가능.

### Phase 2 — 코딩 루프 계약 · 예상 2–3주

`01_cc_loop.md` P0 + 툴 오케스트레이션.

1. **합성 tool_result + 실제 cancel.** `InProcessRunInterrupter` 스텁 제거. Stop 시 모든 pending id가 error result로 체크포인트. resume 요청이 유효.
2. **배치 실행.** `neos/coding/tools/orchestrator.py`. 한 assistant 메시지의 연속 READ_ONLY는 한 safe-point/한 checkpoint. write+read 혼합은 read 배치 후 write 단독. mutate 병렬 금지.
3. **steer를 실루프 transcript에 결합.** `pending_instruction`을 다음 모델 턴의 user 메시지로. tool_result와 섞지 않음.
4. **승인 경고.** `approval_display_summary`에 argv 기반 `warnings[]` (rm -rf, reset --hard, force push). 자동허용 확대는 하지 않음. pytest/ruff는 “세션 규칙 후보”로만 표시.
5. **`todo_write.v1`.** `loop_state.todos` 스텁을 실루프로 연결.
6. **계층 compact.** 해시 드롭 대체: 오래된 tool_result 축약 + 활성 tool 쌍 유지 + 임계값 시 요약 턴 1회 + 실패 서킷 브레이커.
7. **훅 포트 (no-op).** Pre/Post tool, Stop, Compact. API 에러 시 Stop 훅 미실행 (CC와 동일, 사망 나선 방지).

완료 (2026-09-11): 합성 aborted tool_result + 실제 task cancel, 선행 READ_ONLY 배치(최대 10), steer `pending_instruction` → user 메시지, 승인 `warnings[]`, `todo_write.v1`, 계층 compact(활성 tool_id 쌍 유지), no-op 훅 포트. `tests/coding/loop` + tools + approvals + durable slices 통과.

의존: Phase 1의 Edit이 있으면 compact/검증 문장이 의미가 있다. 없어도 1–3은 착수 가능.

### Phase 3 — 원격 호출을 “개인 비서 수준”이 아니라 “안전한 원격 콘솔”로 · 예상 2–3주

`04_hermes_remote.md` A→B 순서. Phase 0 게이트가 전제.

1. **세션 키 v2.** `{channel}:{workspace_or_guild}:{chat}:{thread}` (+ 옵션 user). 기존 `slack_C…`와 버전 prefix로 공존. 응답은 `thread_ts` / Discord reply에 고정.
2. **in-flight lock + 👀/✅/❌.** 같은 세션 재진입 방지. 큐 vs drop은 설정 (기본 drop + “처리 중” 한 줄).
3. **워크플로 승인 브리지.** Slack/Discord 버튼 또는 `!approve`/`!deny` → 기존 `approval_handlers.respond_to_approval`. 웹 SSE 경로 유지. 이중 재개 레이스를 테스트.
4. **코딩은 명시적 커맨드만.** `/code` · `!code` → `CodingTaskService` in-process. task_id를 스레드에 바인딩. 채널 principal → 프로젝트 멤버 매핑이 없으면 거부.
5. **`/stop` `/status`.** 워크플로와 코딩 각각 기존 cancel/snapshot API로.
6. 미디어 in은 이 페이즈 말미. Slack private CDN 토큰·SSRF 가드 없이 열지 않음.

완료 (2026-09-11): 세션 키 `v2:{channel}:{scope}:{chat}:{thread}`, 스레드/답글 고정, in-flight drop, `/code`는 `coding_invoke`+owner일 때만 CodingTaskService (워크플로 미호출). `/stop` `/status` `!approve`/`!deny`는 스레드에 바인딩된 코딩 태스크. 미디어/Block Kit 없음. `tests/api/channels/` 통과.

의존: Phase 0. 코딩 원격(4–5)은 Phase 2의 cancel이 있어야 `/stop`이 의미가 있다.

### Phase 4 — 자기개선 (검증 게이트 있는 학습) · 예상 2–3주

`05_hermes_self_improve.md`. Hermes 기본값(review fail-open, write_approval OFF)을 **뒤집어서** 가져온다.

1. **정책 플래그.** `learn.write_approval` 기본 ON. bundled/레포 스킬 불변. 학습 아티팩트 네임스페이스 `org/user/workspace`.
2. **`MemoryManager.learn()` 배선.** Vote `feedback_category` (`013_`), refinement 소스 선호 (`017_`), 워크플로 종료 시 구조화 fact. 명령형 문장 필터 + 캡. 에피소드 500자와 분리.
3. **코딩 런 교훈.** 런 종료 Celery 후처리. 입력: `coding_events` + 마지막 테스트/린트 로그. 출력: staged markdown lesson. **승인 전에는 다음 런 프롬프트에 넣지 않음.** 실행 스크립트 생성 금지.
4. **연구 절차 스킬 (문서만).** 성공한 파이프라인의 클래스 레벨 절차 (`pdf-html-gate` 등). 인덱스는 60자 description. 본문은 on-demand. `skill.py` 자동 생성 금지.
5. **Beat curator.** `neos/tasks/curate_learned_skills`. 24h. 결정론적 stale/archive만. pin과 scheduled_task 참조 스킬 보호. LLM consolidate 기본 OFF. 스냅샷은 object storage.
6. **세션 검색 도구.** 기존 `message_embeddings` hybrid. Hermes 4형태(query/scroll/read/browse)를 축소. LLM 요약 층 없음. `user_id` 강제.

완료 (2026-09-11): `learn()`에 명령형 필터+캡. Vote 피드백·에피소드 fact 배선. 코딩 실패는 staged lesson (승인 전 `## Lessons`에 없음). Beat curator prune-only. `search_user_sessions`는 `user_id` 필수. Honcho/`skill.py` 자동 생성 없음.

의존: 코딩 교훈은 Phase 2 이벤트 모델. 채널과 독립이므로 Phase 3과 병렬 가능.

### Phase 5 — 후속 (메트릭을 본 뒤)

착수 조건: Phase 1–2 코딩 태스크의 완료율·재시도율·평균 툴 횟수가 베이스라인 대비 측정되어 있다.

- `AGENTS.md` / `CLAUDE.md` bootstrap (user context, 토큰 캡, injection fence). 시스템 프롬프트에 넣지 않음.
- explore / implement / verify **페이즈** (프로세스 분리 전).
- 코딩 전용 스킬 2개: `verify`, `commit` (요청 시에만, 훅 스킵 금지).
- `ask_user.v1` 또는 plan 페이즈.
- 정적/동적 프롬프트 분할 + Anthropic `cache_control` (도구 목록이 안정된 뒤).
- prompt-too-long → compact 재시도, max_output_tokens escalate.
- 스트림 중 READ_ONLY 실행 (이득이 읽기 폭주 턴에서만 — 측정 후).
- `spawn_agent.v1` RO Explore. coordinator/team은 계속 비목표.
- 코딩 WebFetch allowlist (세션 밖 HTTP, `execute` curl 금지).
- Deferred ToolSearch — 툴이 ~20개를 넘을 때.
- Discord auto-thread, Block Kit, draft streaming, pairing.

완료 (2026-09-11, 일부): `AGENTS.md`/`CLAUDE.md`는 첫 턴 user 메시지(fence, 16KiB). explore/implement/verify 페이즈. `ask_user.v1` 승인 필요. `load_skill.v1` verify/commit 마크다운. 413 → compact 1회 재시도. `max_tokens` 1회 escalate. 시스템 프롬프트 정적/동적 `cache_control`. spawn_agent, WebFetch, ToolSearch, 스트림 중 RO, Discord UX는 남김.

## 6. 테스트 · 관측 · 롤백

### 테스트

- 코딩: 기존 `tests/coding/loop/`, `tests/coding/tools/`를 계약 테스트로 확장. 새 루프 동작은 fake sandbox + fake model로 닫는다.
- 채널: `tests/api/channels/` 신설. Bolt/discord.py는 어댑터 경계를 목킹하고 게이트·세션 키·라우팅만 실측.
- 학습: staged lesson이 미승인 상태에서 프롬프트에 안 실리는지, curator가 bundled를 안 건드리는지, 세션 검색이 `user_id`를 강제하는지.

브라우저 검증: Phase 1–2는 Code UI의 승인·Stop·todo·diff가 기존 웹소켓 계약과 맞는지 `web/tests/` 코딩 경로를 회귀. Phase 3은 Slack/Discord를 실계정으로 보지 않고 어댑터 단위 + 웹 승인 화면의 이중 재개만 확인한다. 이 계획 문서는 UI를 바꾸지 않는다.

### 관측

코딩: `task_id` / `run_id` / `turn_id` / `tool_call_id` baggage는 `NEOS_CODING.md`가 이미 요구. Phase 2에서 배치 크기, compact 발화, 합성 result 수를 카운터로.

학습: 생성 수, 승인율, 이후 런 재사용률. 재사용 없는 자동 생성은 끈다.

채널: 게이트 drop 사유(mention/allowlist/ignored/bot)별 카운터. 워크플로 호출 수가 게이트 전후로 떨어짐을 배포 게이트로 본다.

## 8. 권장 착수 순서 (이번 사이클)

병렬 두 갈래로 시작한다.

```
주 1:  Phase 0 채널 게이트 + Phase 1 프롬프트/Edit
주 2–3: Phase 2 루프 계약 (합성 result → 병렬 RO → steer → compact)
주 3–5: Phase 3 원격 (/code는 cancel이 생긴 뒤)  ∥  Phase 4 learn()+staged lesson
주 6+:  Phase 5는 메트릭 보고 후 별도 계획
```

첫 PR 후보 (각각 단독 머지):

1. `channels/authz.py` + 세 어댑터 게이트 + `tests/api/channels/`
2. `neos/coding/prompts/` 빌더 + description 교체 + 스냅샷 테스트
3. `edit_file.v1` + Read offset/limit + 사전 Read 계약

이 세 PR이 랜딩하면 코딩 품질과 채널 안전이 동시에 움직이고, Phase 2–4는 그 위에 쌓인다.
