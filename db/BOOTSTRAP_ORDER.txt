# 배포 스키마의 정본 적용 순서 (SCHEMA1)
#
# 이 파일이 순서의 **정본**이다. `db/README.md` 의 산문이 아니다.
#
# 2026-09-20 에 69줄 전량 나열에서 **규칙 선언**으로 바꿨다. 그전에는 새 마이그레이션마다
# 한 줄씩 손으로 적어야 했고, 69줄 중 실제로 판단이 들어간 것은 예외 3줄뿐이었다.
# 이제 마이그레이션은 **번호순으로 자동 유도**되고, 이 파일에는 자동 유도로 얻을 수 없는
# 것만 적는다. 새 마이그레이션을 더할 때 보통은 이 파일을 건드리지 않는다.
#
# 자동 유도로 바꾸면서 잃을 뻔한 것이 하나 있었다. 목록을 손으로 들 때는 "어디에 넣을까"가
# 사람의 판단이었고, 그 판단이 실제로 060 을 구했다 (아래 [hoist] 참조). 자동 append 였다면
# 맨 뒤에 놓였을 것이고 그것은 **에러가 아니라 침묵**이다. 그래서 그 판단을 기계 검사로
# 옮겼다 -- `verify_schema_bootstrap.py` 의 가드 검사가 `information_schema.tables` 로 선행
# 테이블을 요구하는 블록을 전부 찾아, 그 테이블을 만드는 파일이 앞에 있는지 확인한다.
# 사람이 주석에 적어 둔 것보다 많이 찾아냈다 (014 는 예전 주석에 없었다).
#
# 규칙 셋:
#   1. 빈 줄과 `#` 로 시작하는 줄은 무시한다
#   2. `[base]` 의 경로는 저장소 루트 기준, `[hoist]` 는 파일명만 쓴다
#   3. `db/*.sql` 중 `[base]` 에 없는 파일이 있으면 검증이 실패한다
#   4. `db/migrations/*.sql` 은 `NNN_이름.sql` 이어야 하고 번호순으로 자동 포함된다 --
#      이름 규칙을 어기면 검증이 실패한다(자동 포함의 대가로, 아무 파일이나 딸려
#      들어가지 않게 하는 울타리다)
#
# 검증: `make db-verify` (전량 적용 + 재적용 멱등성까지)
#       `make db-check`  (목록·이름·가드 검사만, Docker 불필요)
